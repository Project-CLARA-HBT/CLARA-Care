# Risk Register — PH13 A10 (Connected Health & Wearables)

| Risk ID | Description | Severity | Likelihood | Mitigation Strategy | Status |
|---|---|---|---|---|---|
| RISK-PH13-A10-01 | Replay of sync batches with modified payloads attempting to inflate physical activity or falsify historical metrics | Critical | Low | Cryptographic digest verification (`_payload_hash`) computes SHA-256 of canonical payload JSON. Replaying an identical key with a different payload trips HTTP 409 Conflict. | Mitigated |
| RISK-PH13-A10-02 | Multi-device concurrent step inflation (e.g. carrying phone while wearing smart watch producing duplicate steps) | High | Medium | Deduplication engine (`_deduplicated_steps`) clusters overlapping intervals and selects the maximum single observation based on primary origin duration coverage, never summing overlapping intervals. | Mitigated |
| RISK-PH13-A10-03 | Ingestion of sensitive health metrics (e.g. blood glucose, blood pressure) without explicit patient consent | Critical | Low | `import_batch` verifies that all requested record types form a strict subset of `ConnectorConsent.data_types_json`. Any unconsented type immediately rejects the entire batch with HTTP 403 Forbidden. | Mitigated |
| RISK-PH13-A10-04 | Continued batch ingestion or synchronization after user disconnects or revokes connector authorization | High | Low | Synchronous in-transaction checks in `import_batch` verify `connector.status in {"connected", "healthy"}` and `active_consent is not None`. Disconnect timestamps `revoked_at` and wipes tokens immediately. | Mitigated |
| RISK-PH13-A10-05 | Cross-profile IDOR access where User A attempts to view or push data into User B's connector | Critical | Low | `owned_connector` scopes queries to `user_id == current_user.id`, returning HTTP 404 Not Found (obscure-existence) for foreign IDs. `import_batch` strictly validates `payload.profile_id == connector.profile_id`. | Mitigated |
| RISK-PH13-A10-06 | Corrupted or absurd biometric data (e.g. 500 bpm HR, negative steps, NaN/Inf) causing calculation errors or panic | Medium | Low | Pydantic model validators `validate_shape_and_finiteness` and `validate_record_semantics` reject non-finite and physiologically impossible values at the API ingress boundary with HTTP 422. | Mitigated |
| RISK-PH13-A10-07 | Vendor cloud API rate limit exhaustion (e.g. Fitbit 150 req/hr per user) causing sync worker starvation | Medium | Medium | Sync worker implements exponential backoff, respects `Retry-After` headers, and transitions connector status to `rate_limited` rather than aggressively hammering vendor endpoints. | Mitigated |
| RISK-PH13-A10-08 | Plaintext leakage of OAuth refresh tokens in database dumps, traces, or application logs | Critical | Low | Tokens stored using AES-256-GCM ciphertext (`token_ciphertext`) with versioned keys. Application logs, Sentry spans, and Prometheus metrics sanitize all credential and biometric payloads. | Mitigated |
| RISK-PH13-A10-09 | Timezone shifts and cross-meridian travel causing misallocation of steps across calendar dates | Low | Medium | All records require explicit timezone offsets (`require_timezone`, `validate_zone_offset`). Daily projection normalizes timestamps to UTC date boundaries (`_as_utc`). | Mitigated |
