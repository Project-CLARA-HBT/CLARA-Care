# Risk Register — PH13 / A03 (Wearable Dedup and Multi-Source Version Mapping)

| Risk ID | Description | Severity | Likelihood | Mitigation | Status |
|---------|-------------|----------|------------|------------|--------|
| RISK-PH13-A03-01 | Destructive deduplication silently drops legitimate samples from a second source, biasing a health trend | Critical | Low | Cross-source disagreement never deletes: engine returns `CONFLICT_PRESERVED` and lists every conflicting key. Only identical values collapse to `DUPLICATE_SKIPPED`. Provenance keys are returned for all retained records. | Mitigated |
| RISK-PH13-A03-02 | Non-deterministic keys split one provider record into multiple rows across processes/restarts | High | Low | Keys are SHA-256 over RFC-8785-style canonical JSON (`sort_keys`, compact separators) of provider + external id + metric + normalized UTC window + canonical value/unit. Tested for byte-stability. | Mitigated |
| RISK-PH13-A03-03 | Stale replay overwrites a newer provider revision (lost update) | High | Low | Revision identity excludes value, ordering is `(freshness, method, source, key)`; older/equal replay returns `SUPERSEDED` with `preferred_key` pointing at the retained newer record. | Mitigated |
| RISK-PH13-A03-04 | Device-vs-cloud precedence hides a clinically more accurate cloud value | Medium | Medium | Precedence is a *preference label*, not a delete. Losing values remain in the returned conflicting set so downstream projections can display provenance. Source class mapping is overridable per deployment. | Mitigated |
| RISK-PH13-A03-05 | Unreviewed engine activates before clinical/UX approval | High | Low | `lifemap_wearable_dedup_enabled` defaults `False`; both `evaluate` and `map_versions` raise `WearableDedupDisabledError` (fail-closed) instead of degrading silently. | Mitigated |
| RISK-PH13-A03-06 | Batch result depends on concatenation order of provider pages | Medium | Low | `map_versions` sorts by revision identity and returns decisions keyed by dedup key; test asserts forward == reverse `to_dict()`. | Mitigated |
| RISK-PH13-A03-07 | Naive timestamps from a provider adapter create ambiguous keys | Medium | Low | `_utc` raises `ValueError` for timezone-naive datetimes; the canonical schema already rejects naive timestamps at the boundary. | Mitigated |
| RISK-PH13-A03-08 | Tie between two equal-precedence sources yields unstable winner | Low | Low | Total order includes a deterministic `tiebreak` (dedup key hash), so ties resolve identically on every host. | Mitigated |
| RISK-PH13-A03-09 | Unit drift (e.g. `count` vs `steps`) conflates different metrics | Medium | Low | `record_metric_key` and `record_dedup_key` both include record type and unit; different units never compare equal. | Mitigated |
| RISK-PH13-A03-10 | Engine is bypassed by direct DB writes, leaving duplicate rows | Medium | Medium | This module is a pure decision layer only; wiring into `connected_health/ingestion.py` is intentionally out of this lane and must be a follow-up with its own regression tests. Documented as a known integration gap. | Open (accepted, out of lane) |
