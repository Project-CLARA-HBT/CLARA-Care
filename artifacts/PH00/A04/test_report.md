## 3. Subsystem Architecture & Contract Findings

### 3.1 Database & Pipeline Decoupling
- **No Shared Foreign Keys:** `services/api` (relational models in `clara_api.db.models`) and `services/ml` (corpus models in `clara_ml.rag.store.schema`) operate with decoupled persistence boundaries.
- **API to ML Gateway Communication:** The API gateway calls ML strictly via HTTP/WebSocket (`http://localhost:8110`), authenticating with `X-ML-Internal-Key`.
- **Additive Extension DDL:** `services/ml` manages its own 10 tables (`kb_*` and `eval_*`) with dedicated pgvector and pg_trgm indices using `clara_ml.rag.store.migrations.run_migrations`.
- **Graceful Startup Self-Check:** In environments where pgvector is absent, `clara_ml.rag.store.health.run_startup_self_check` automatically falls back to the in-memory knowledge store, ensuring zero startup crashes.

### 3.2 Model Registry & Task Routing
- **Strict Task Registry:** 21 closed tasks with schema version `clara.task-contracts.v2`.
- **Capability Enforcement:** `ModelGateway` validates required capabilities (`text`, `structured_output`, `long_context`, `asr`) before routing requests to adapters.
- **Zero-COT Compliance:** Reasoning content (`<think>...</think>`) is filtered and sanitized across all endpoints to comply with zero-COT safety requirements.

### 3.3 Provenance & Audit Integrity
- **PII-Safe Telemetry:** Request and prompt contexts are fingerprinted via `compute_context_digest` (`sha256:...`); raw text or patient data is never logged to telemetry or Prometheus counters.
- **FIDES Tighten-Only Combiner:** `RagPipelineP1.tighten_fides_verdict_with_trust` guarantees that low-authority or stale retrieved knowledge can only escalate borderline warnings to blocks, never weaken an existing critical gate.
