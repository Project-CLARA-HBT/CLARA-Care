# Risk Register — Subagent A05 (Web UX)

| Risk ID | Risk Category | Severity | Likelihood | Impact Description | Path:Line Anchor | Mitigation / Remediation Action |
|---|---|---|---|---|---|---|
| **RSK-A05-031** | Third-Party Telemetry & PHI Leakage | HIGH | LOW | Using external CAPTCHA providers (such as Google reCAPTCHA) transmits client IP addresses, browsing contexts, and telemetry to third-party CDNs, violating CLARA's strict privacy invariants. | `apps/web/components/auth/auth-security-challenge.tsx:1-90` | Implemented a self-contained, privacy-preserving, zero-dependency client-side arithmetic challenge that requires zero external network calls, preserves privacy, and operates in offline/isolated environments. |
| **RSK-A05-032** | Client-Side Lockout Bypass via Refresh | HIGH | MEDIUM | If rate-limit and attempt counts reside solely in volatile React state, an attacker or script could bypass lockout and cooldown delays simply by reloading the web page. | `apps/web/lib/auth-rate-limit.ts:31-70` | Synchronized attempt counts and lockout expiration timestamps with browser `sessionStorage` with graceful fallback to in-memory storage, ensuring persistence across page reloads without storing passwords or tokens. |
| **RSK-A05-033** | Shared Device Credential Collisions | MEDIUM | LOW | Multiple users accessing CLARA on the same public workstation could encounter lockout due to an earlier user's failed attempts. | `apps/web/lib/auth-rate-limit.ts:72-76, 175-188` | Partitioned rate limit states by authentication context (`login` vs `otp`) and normalized email identifier. A successful login immediately clears that account's rate-limit record. |
| **RSK-A05-034** | Server 429 Retry-After Desynchronization | MEDIUM | MEDIUM | Inconsistent backend rate limit responses (e.g., header `Retry-After` vs JSON body `retry_after_seconds` vs localized detail strings) could cause the client to fail to display the correct lockout time. | `apps/web/lib/auth-rate-limit.ts:80-128` | Implemented a multi-tier extractor in `extractRetryAfter` inspecting direct error properties, response headers, response data fields, and localized regex string patterns in both Vietnamese and English. |
| **RSK-A05-035** | Accessibility / Assistive Tech Impedance | MEDIUM | LOW | Security challenges that rely on non-semantic visuals or lack keyboard accessibility prevent visually impaired or assistive technology users from completing authentication. | `apps/web/components/auth/auth-security-challenge.tsx:85-155` | Structured challenge with WCAG 2.1 AA compliant semantics (`role="region"`, `role="alert"`, descriptive aria-labels, touch target sizing, high-contrast tokens, and keyboard-driven refresh capability). |
