# Risk Register — PH12 A01 (LifeMap Timeline Event Query API)

| Risk ID | Description | Severity | Likelihood | Mitigation | Status |
|---|---|---|---|---|---|
| RISK-PH12-A01-01 | Premature activation of longitudinal timeline query endpoints before clinician and multi-profile privacy sign-off | High | Medium | Endpoints gated behind `LIFEMAP_TIMELINE_QUERY_V2_ENABLED` defaulting to `false`. Requests fail closed with HTTP 404 (`lifemap_timeline_query_v2_disabled`) when flag is absent or disabled. | Mitigated |
| RISK-PH12-A01-02 | Direct identifier (PHI/PII) leakage across consumer or clinician longitudinal timeline views | Critical | Low | Direct identifiers (`citizen_id`, `ssn`, `cmnd`, `cccd`, `phone`, `email`, `dia_chi`, `bank_account`, `passport`, `bhyt_raw`) are recursively scrubbed to `[REDACTED_PHI]` via `_sanitize_event_payload`. Vietnamese clinical title mapping derives safe event labels. | Mitigated |
| RISK-PH12-A01-03 | Performance degradation and database latency on large longitudinal event histories via deep offset pagination | High | Medium | Implemented bitemporal keyset pagination with opaque base64url cursor tokens (`v1:{sort_by}:{iso_timestamp}:{event_id}`) enabling index seek execution. Page limit strictly bounded to 200 items (default 50). | Mitigated |
| RISK-PH12-A01-04 | Cross-profile or cross-tenant data leakage in multi-profile family care environments | Critical | Low | All timeline queries strictly scoped through `_scope(db, token, x_profile, action="view")`, verifying profile ownership, RBAC permissions, and versioned medical consent before executing queries. | Mitigated |
| RISK-PH12-A01-05 | Cursor tampering or sort mismatch causing unhandled server exceptions or arbitrary scan skipping | Medium | Low | `_decode_timeline_cursor` enforces version prefix `v1`, validates ISO 8601 UTC timestamp and integer ID, and asserts sort dimension equality, raising HTTP 422 with descriptive code on discrepancy. | Mitigated |
