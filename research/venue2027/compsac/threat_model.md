# COMPSAC-threat · Threat, trust and failure model — Dependency-Complete Optimistic Admission for Concurrent Clinical AI Writes

- **Task:** `COMPSAC-threat` (Phase P01, venue `compsac`, priority `P0`)
- **Upstream dependencies:** `COMPSAC-scope` (PASS, `proof/COMPSAC-scope.json`), `SH-research_ethics` (PASS, `proof/SH-research_ethics.json`)
- **Model version:** `compsac-threat-model-v1`
- **Validator:** `research/venue2027/_shared/tools/threat_model.py` (`validate_threat() -> ThreatCoverage`, `THREAT_MODEL_VERSION 1.0.0`)
- **Scope of this model:** the machine-checkable dependency-closure oracle and the scope-local optimistic admission protocol (arm B4) for AI-generated clinical writes, together with its benchmark arms B0–B3 and the exported history format judged by the independent checker. This is a *designed* threat model for a synthetic-only study (per `SH-research_ethics`); it freezes the adversary, trust, and failure semantics that `COMPSAC-schema`, `COMPSAC-oracle`, and `COMPSAC-baselines` must implement against. It makes no empirical claim: every oracle verdict below is an *expected* label from the frozen `CASE_MATRIX.md`, not an observed result.

## 1. System and adversary overview

The system under attack is the clinical write-admission pipeline: an AI-generated clinical write operation (medication, allergy, history, purpose-grant mutation) arrives with a per-operation dependency schema; the candidate (B4) validates every required read/write edge version plus the consent/policy epoch inside one database transaction under canonical lock ordering, then commits. Histories are exported to an independent checker (Elle-style, per the novelty contract `F6`). The adversarial target is the gap between what the pipeline *believes* it validated and what the database *actually* serialized.

Three failure axes organize the families: (a) **time** — the adversary wins if validation reads a stale version or epoch (revocation timing, stale-witness reuse); (b) **closure** — the adversary wins if a semantically required dependency is omitted so skew survives validation (omitted dependencies, DB-level isolation anomalies); (c) **authority** — the adversary wins by confusing who adjudicates (model agency, actor/oracle confusion, insider/observer collection). Each family below is paired: a `clean` control that must be accepted or correctly rejected for benign reasons, and an `adversarial` case that must be detected, rejected, or counted as `INDETERMINATE` — never silently passed. Timing is logical (`logical_time` from the `clara.venue2027.scenario.v1` record); wall-clock is observable but never used as a correctness argument.

## Attacker and observer capabilities

**Attacker (Mallory, concurrency adversary).** Capabilities, in increasing strength:

- **A1 — Schedule manipulation.** Controls the interleaving of concurrent writers: ordering of two writers' lock acquisitions, interleaving of a consent-revocation transaction with a clinical write, and timing of a dependent write behind an omitted dependency. This is the RQ2 adversary: she can force any interleaving permitted by the DB isolation level, but cannot break the DB's own serialization guarantees.
- **A2 — Dependency-schema omission.** Supplies or influences the per-operation dependency closure the candidate derives — e.g., a generated closure that omits a required allergy edge. She cannot modify the frozen per-operation dependency schema itself (that is versioned and signed in `COMPSAC-schema`), but the *instance* closure for one operation may be wrong.
- **A3 — Version/epoch forgery and stale-witness reuse.** Reuses an old lease, version stamp, or read-set witness from a previous transaction; presents a stale consent epoch as current; reuses a validated read-set token beyond its transaction. She can also forge application-level stamps; the model's answer is that only DB-visible state adjudicates, so forged application stamps are irrelevant (see §Trusted components).
- **A4 — Model agency abuse.** Perturbs the AI model's generated write payload or its derived dependency closure (e.g., by prompting or input-shifting) so that a semantically required cross-resource read is left out; re-submits the same logical operation ID with mutated payloads to exploit idempotent-retry semantics; resubmits after rejection hoping validation windows drift.
- **A5 — Baseline-arm pollution.** Attempts to weaken a comparator (B0–B3) — e.g., starving B2's SSI of indexes so it aborts more, or giving B4 a warmer cache — to manufacture a frontier claim. Countermeasure: equal-budget, pinned-fidelity baseline harness is a *control-plane invariant*; a frontier claim without baseline parity is a stop-and-revise violation, and `NOT_RUN_EXTERNAL` blocks comparative claims.

**Observer (Eve, passive).** Capabilities:

- **E1 — History visibility.** Reads exported transaction histories, exported per-case artifacts (`case.json`, `truth.json`, `observed.json`), and arm-level counts (eligible/attempted/completed/rejected/abstained/indeterminate/timeout/environment-failure/not-run-external). She may *audit* but not *adjudicate*: she can flag a suspected anomaly for the independent checker, but truth labels derive from event sequence and policy/DB ground truth, not from candidate reason codes (GATES/INDEPENDENT_EVIDENCE_PROTOCOL.md §2).
- **E2 — Metric observation.** Sees throughput, p50/p95/p99 latency, retry amplification, false-stale and forbidden-commit rates per arm. She must not infer clinical truth from these (synthetic identities only; no patient records exist in this study).
- **E3 — Privacy boundary.** All identities, timestamps, and resource ids are synthetic; the observer can compute PII-free aggregates but the dataset contains no real patient data to expose (ethics gate `SH-research_ethics`, dataset declaration `synthetic-compsac-2027`).

Neither attacker nor observer can read the adjudicator's private memory or non-exported state; the only legitimate adjudication inputs are the exported history and the frozen dependency schema (oracle independence, `F4`/`F6`).

## Trusted components

Trust is granted to *components*, never to model output or to any statistical aggregate.

- **T1 — PostgreSQL DBMS (pinned release/version, recorded isolation setting).** The single serialization point of truth. Serializable snapshot isolation (SSI) under `SERIALIZABLE` and row/predicate locking under lower levels are trusted to implement their documented semantics (Ports & Grittner 2012). Every claim about real PostgreSQL behavior must come from real PostgreSQL runs; SQLite observations are structurally incapable of supporting SSI claims (novelty contract §5.2 refusal).
- **T2 — Schema-defined dependency oracle.** The frozen per-operation dependency schema (required read/write edges, epoch anchors) produced by `COMPSAC-schema` and adjudicated by the separate `COMPSAC-oracle`. Trusted to be *complete by construction review* — the study's own RQ2 measures whether the derivation is complete, and an omitted required edge is a detected defect (`COMPSAC-CASE-04`), not a trusted property. The oracle never imports candidate code; if it can only adjudicate by introspecting candidate internals, independence is broken and the study stops and rebuilds the oracle.
- **T3 — Version/epoch anchors.** Per-resource version counters and consent/policy epoch registers *as materialized in the database*. Application-level caches, leases, and read-set witnesses are **untrusted mirrors**: they are advisory only, and any validation that relies on them fails closed with a stable reason code.
- **T4 — Canonical lock-order table.** The frozen total order over resource classes used to prevent deadlock (`COMPSAC-CASE-06`). Trusted as configuration; deviations are detected as violations, not hidden.
- **T5 — Independent history checker.** The Elle-style checker (`elle20`) that receives exported histories and returns anomaly verdicts. Trusted as a black box (histories in, anomalies out); never trusted to know candidate internals.
- **T6 — Task/state infrastructure.** `agent_protocol.py` report validation, SHA256 artifact binding, on-disk command logs. Trusted for process integrity, not for any scientific claim.

Not trusted: the AI model's payload or its self-derived dependency closure (A4); application-level lease/version stamps (A3); baseline self-reports (A5); wall-clock timing as a correctness witness; statistical confidence or digests as clinical reasoning proof (task §4).

## Excluded domains

Explicitly **out of scope**, with the reason each exclusion is safe here:

- **X1 — Network partition and Byzantine nodes.** The concurrency study models benign contention over a correct DB channel (novelty contract §5.1: "COMPSAC needs benign-contention and dependency scope"). Crash/recovery and lossy-durability questions are DSN's separate endpoint; no crash cut-points are injected and no recovery journal is built here. Partition-induced divergence cannot arise because there is exactly one DBMS serialization point (T1).
- **X2 — Compromised DB superuser.** A superuser can rewrite history and disable enforcement; no protocol above the DBMS defends against this. Excluded on capability grounds: the adversary cannot obtain superuser in the threat model, and the audit trail (T6) plus DB-level logging would expose such an actor operationally. Consequence: DBMS kernel bugs are also out of scope; we trust T1's documented semantics and record the pinned version so defects are traceable.
- **X3 — Cryptographic breaks of the infrastructure.** SHA256 artifact binding (T6), and any signature scheme on the dependency schema, are assumed unbroken. The threat model never substitutes a digest for a semantic judgment.
- **X4 — Side channels and timing oracles.** Latency distributions are *measurements*, not leak channels; no secret exists whose confidentiality could be attacked through them (synthetic data only).
- **X5 — Real-patient harm.** The study population is synthetic (`synthetic_only: true` in every case record). Clinical validity is out of scope; no extrapolation from synthetic security results to safe patient treatment (GATES protocol §9).

## Attack family and control matrix

Every family row carries **both** a `clean:` control and an `adversarial:` case. `Expected oracle verdict` is the frozen truth label per `CASE_MATRIX.md`; where two labels are admissible the pair is kept (`REJECT_OR_RECOMPUTE`, `DENY_OR_INDETERMINATE`) and `MEASURE`/`INDETERMINATE` is never coerced to PASS. Family ids match `ATTACK_FAMILIES` in the shared validator; COMPSAC-specific anomalies map onto them as noted per row and in the mapping table below.

### COMPSAC-specific anomaly → validator-family mapping

The task brief names eight COMPSAC-specific threats; each lands in a validator family (and, where the DB adjudicates, may *also* be visible to T1/T5):

- **Concurrent clinical AI writes** → `revocation_timing` + `purpose_scope` (A1 interleavings; CASE-01/06/07 clean controls).
- **Write skew from omitted dependencies** → `model_agency` (A2/A4; CASE-04; B3 is the expected-exhibit ablation).
- **Consent/policy epoch races** → `revocation_timing` (CASE-03).
- **Stale read-set acceptance** → `replay` (A3; DB-visible revalidation required).
- **Lease/version forgery** → `replay` (A3; application stamps are untrusted mirrors).
- **DB-level isolation anomalies (SSI false negatives)** → `purpose_scope` (CASE-05/09; a *benign* SSI anomaly that the strong baseline itself exhibits is recorded as such — it weakens no candidate claim and is never relabeled a candidate defect; SSI false negatives are detected by exporting the history to T5, not by trusting B2's self-report).
- **Actor/oracle confusion** → `insider_or_observer` (oracle independence, `F4`/`F6`).
- **Model agency and replay power** → `model_agency` + `replay` (A3/A4).

**Revocation/schedule time semantics.** All ordering is logical time (`logical_time` in the scenario record); the commit-time read of consent/policy epochs is the binding event. "Revoked before write" means the revocation transaction serialized before the write's commit-lock acquisition; validation of any earlier epoch read is then insufficient. Retry loops must re-derive the full closure per attempt; a retry that reuses a prior attempt's read set is a `replay`-family violation.

**Model agency and replay power.** The AI model is an *untrusted payload and closure producer*: its output is validated, never believed (A4). Replay power is bounded by stable logical operation IDs plus DB-visible version checks: identical (ID, payload) retries are idempotent; anything else fails closed.

## Oracle and actor authority

Defined, and authority is non-overlapping:

- **Truth authority (oracles):** the independent dependency-closure/history checker (T5 + T2) adjudicates all anomaly and detection verdicts from exported histories and the frozen dependency schema. It never imports, reads, or introspects candidate code (novelty contract `F4`, `F6`; CASE_MATRIX QA rule). Truth labels are frozen in `truth.json` before any arm runs.
- **Actor authority (who may produce evidence):** only the instrumented benchmark harness may produce `observed.json` artifacts, and only the frozen protocol may produce `truth.json`. The candidate (B4) is an *actor*, never an adjudicator of its own outcome; baselines B0–B3 are actors under the same harness with equal budget.
- **The observer (Eve) has no authority:** she may flag and audit (E1) but cannot label truth. A flagged case returns to the independent checker; pending that, the case is `INDETERMINATE` and is counted in the denominator — an undefined or disputed authority is never treated as safe.
- **No authority may be assumed from:** model confidence, cryptographic digests, timing, or arm-level aggregates. If any authority is genuinely undefined for a case class, the class is registered as `INDETERMINATE` upstream (CASE_MATRIX rule) and the run stops rather than passes.

**Failure semantics (stable reason codes, never silent):** `CONSENT_EPOCH_STALE` (revocation_timing adversarial), `VERSION_MISMATCH_REPLAY` (replay), `CLOSURE_INCOMPLETE` (model_agency), `PURPOSE_SCOPE_SKEW` (purpose_scope), `ORACLE_AUTHORITY_VIOLATION` (insider_or_observer), `INDETERMINATE_UNRESOLVED`, `ENVIRONMENT_FAILURE`. Errors are returned as stable codes with the failed attempt's context; a rejection is never silently counted as a safe completion, and every code above is machine-checkable evidence for the mapped family.

## Verification and falsification hooks

- The shared validator must return `ok: true` on this file (`research/venue2027/compsac/tests/test_threat_model.py` asserts it, plus the adversarial incomplete-model case).
- Falsification rule inherited unchanged from the blueprint: any forbidden commit under a complete, independently labeled dependency schedule falsifies the safety claim; if fully serializable PostgreSQL is as fast, the null performance benefit is reported candidly.
- Zero observed forbidden commits is a confidence bound (`1 - 0.05**(1/n)` one-sided 95% upper bound under independent Bernoulli trials), not logical proof (GATES protocol §6).
