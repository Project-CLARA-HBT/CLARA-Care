# External dialogue-state development replay

This supplemental analysis uses every dialogue of SGD train/dialogues_001.json at upstream revision e852981ae34990f4358979625854259302feaa78. The adapter accepts only the SHA-256 of that file. No other shard, validation/test split, LongMemEval variant or registered confirmatory data enters selection. This is a separate development population outside the registered synthetic estimand.

Within each dialogue, preserve user-turn order and enumerate every active frame's annotated state slots in lexical slot order. One slot occurrence schedules one single-field projection. Version identity follows observed equality of the service, slot name and value list within that dialogue. Record anonymized scope and version ordinals only. Repeated annotations model demand for state reads. They are not observed external API calls. Utterances, original values, service names and original IDs are omitted.

The overlay gives each service-slot its own purpose. Revoke the first observed purpose at the midpoint (floor of half the user-turn count), provided it was observed before the midpoint. Withdrawal applies to every version, including versions first requested afterward. Each dialogue is one cache partition with a shared cold start. A successful miss caches an identity projection in B1 and B4. B1 purges the whole partition at the barrier before looking up the next request. B4 uses the existing candidate and registers a source parent with its true purpose and a derived projection with queue-local authority. A hit must pass the candidate read gate. Both arms rebuild admitted misses from the same live snapshot used by B2 on every request. No warm-up reads, generated retries, simulated expensive reconstruction or replicated requests.

Use the existing independent byte observer against the same source schedule. Capture subprocess data and cancellation pipes. Count matched authorized coverage, forbidden bytes and affected histories, hits conditional on authorization, successful rebuilds, and end-to-end elapsed time including initialization, cache/index construction and teardown. Run three cold serial rounds, rotating B1, B2, B4 order, preserving every timing. Report latency for this local workload only. Retain negative outcomes. Any forbidden bytes trigger stop and revise. No formal superiority or equivalence decision, independent-subject claim, or factorial density test follows from this development sample.
