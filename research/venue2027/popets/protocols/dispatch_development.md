# Paired dispatch development extension v1

This supplement to pilot_plan.yaml uses the original seed 42, frame of 60 and development indices. It measures B2 and B4 on the same known-ancestry source projections. Each eligible history has 3–6 dated visits with two single-attribute purpose grants per visit. Markers are distinct fixed-width synthetic strings. At each visit a prompt reads the first field. Later, a summary, queued retry and fallback request that field, and a fourth request reads the independently authorized second field. The revoked family withdraws the first purpose at the registered barrier. Fresh and cross-purpose histories are controls. Three transitive-gap histories have no specified reconstruction recipe and are excluded before either arm runs. B0 and B3 lack verified external comparators. B1 coarse purge is outside this two-arm comparison.

B2 resolves the source and evaluates its current grant at each send. B4 materializes identity copies along the prompt → summary → retry → fallback chain at the visit, applies purpose revocation and gates each dispatch with the existing candidate cache. The two arms get the same snapshot, logical time, request recipe and timeout. These are scheduled retry and fallback reads over a single IPC transport. Each scheduled request has exactly one field. Both grant and derivation metadata are complete in the selected histories.

The receiver reads data frames from an anonymous pipe across a subprocess boundary. A separate pipe carries cancelled request IDs. Its manifest seals the EOF-delimited byte streams with SHA-256 under the assumption the collector and committed manifest are trusted. The verifier reconstructs the schedule independently of senders and requires one data frame or cancellation per scheduled ID. Both missing and conflicting evidence invalidate collection. Each data frame has an ASCII request ID, tab, raw synthetic attribute bytes and newline. Only the attribute region contributes to byte endpoints. An unrecognized or partial attribute invalidates measurement. The independent observer scores bytes against visit availability, requested origin, purpose and effective retirement time.

The RQ1 denominator counts distinct histories with a scheduled request at or after an actual revocation. Earlier deliveries and never-revoked controls contribute only to descriptive results. Authorized coverage credits each requested source attribute at most once per request and includes authorized cancellations in the denominator. Exact projection also detects duplicates. A complete paired run yields descriptive development measurements only. A positive forbidden-byte result triggers stop and revise. The historical decision-only run retains its original interpretation.

Collect into a new directory with `python -m evaluation.venue2027.popets.dispatch_pilot run DIRECTORY`. Replay the receiver's reconciliation and verify file digests with `python -m evaluation.venue2027.popets.dispatch_pilot verify DIRECTORY`. Subprocess wall time includes startup and fixture construction. It cannot estimate dispatch latency or establish a cost advantage.

The collector issues one scheduled ID at a time and must receive exactly one corresponding frame before advancing logical time. Derived entries carry a queue-local label and an edge to their parent. The candidate must follow reverse edges to retire these copies. End-to-end IPC round-trip time includes scheduling and dispatch processing, with interpreter startup included in the first sample. Each arm runs once in fixed order. Timing is descriptive.
