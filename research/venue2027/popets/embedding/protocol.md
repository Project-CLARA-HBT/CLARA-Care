# Embedding dispatch under a scoped withdrawal

Use all 128 histories in the previously pinned SGD train shard. Restore only the published service, slot and list of values for the requested field version. An allowed read returns a 384-dimensional float32 MiniLM embedding of its deterministic JSON serialization. Permissions and withdrawals remain the fixed experimental overlay. The algorithm observes the same single-source dependency per field as the original state-read benchmark. Text contains public dialogue annotations. Synthetic access control is applied before encoding, and raw text, vectors and per-read hashes stay local to the research host.

Run B1 (full subject purge), B2 (fresh projection and encoder), B4 (the existing two-node provenance graph), and a lazy version-tag implementation. Tags reference the same origin purpose and epoch as B4. At withdrawal advance the withdrawn purpose's version. At lookup compare the saved version to the current one; a mismatch triggers the same authorized reconstruction path. This is a local implementation of versioned cache validation, with no distributed ordering claim. Keep the same model, weights, precision, mean pooling, encoder batch size of one, request sequence and per-arm history isolation. Each build performs a real model forward, including repeated text. No extra sleep, external API or encoder memoization.

Primary operational cost is number of encoder forwards with byte-identical observed delivery and cancellations. A tie against lazy tags retires the strict B4 superiority claim on this workload. Independently reconstruct the grant schedule from raw annotations; verify one 1,536-byte payload on every allowed read and no payload on every denied read. Compare actual output bytes of all arms to the fresh reference through a separate process; publish only counts and input fingerprints. Rotate the four arms cyclically by dialogue ordinal, resetting each cache. Time model-warm replay excluding model load but including serialization and egress writes. Report GPU activity and elapsed wall time descriptively because the shared device cannot supply controlled latency. These are development histories within one workload family. The study does not establish performance on missing lineage, many-to-many dependencies or distributed revocation.

Transactional application caches already track dependencies and use invalidation tags. Zanzibar already addresses authorization consistency across data changes. The question here is narrower: does maintaining explicit ancestry save additional materialization when every delivered field has a known source tag?
