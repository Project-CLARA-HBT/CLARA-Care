# Prospective decision rule for CI failure triage

Question. Does conditioning a test’s next failure risk on its last verdict and the previous suite’s failure burden improve early failure detection under a fixed execution deadline? The hypothesized benefit is distinguishing an isolated persistent failure from a suite-wide disturbance without source code or current-cycle observations.

Use the two ABB CSVs actually shipped in the RETECS mirror at revision 9980ab6035f7a961c56e3b33e202bf2c18d15e6f. Treat each project separately. Within each cycle keep the lowest execution Id per Name, ignoring retries. Order whole cycles numerically. The first floor(0.6N) cycles supply training history, the next through floor(0.8N) form validation, and the remainder are held out. Reveal all first-attempt labels and durations only after ranking each cycle, modeling a fast feedback prefix followed by eventual full execution. Ignore LastResults, LastRun, CalcPrio and input ordering as predictors. Share no history across projects.

Each method gets 25% of the sum of predicted durations of tests present, using the last observed first-attempt duration per test and the median of known tests’ last durations for new tests (one duration unit if the project has no history). Score only the consecutive prefix that completes within that deadline using recorded durations. No peeking to skip a long test. Report zero-failure cycles. Primary metric is the mean fraction of failing tests found per failure-bearing cycle, weighted equally across projects. Secondary is whether any failure is found on those cycles. Preserve numerator, denominator, budget, and prefix cost for every evaluation cycle and arm.

Candidate uses additive shrinkage of per-test failure counts within (previous test verdict including unseen, previous cycle failure proportion binned at 0.1 and 0.5) towards the pooled project rate for that context, then divides risk by predicted duration. Choose pseudocount from 2, 8, 32 on validation across both projects. Ground the ablation in the same estimator without the previous-cycle burden.

Comparators include shortest first, MostFail, LatestFail, LatestTrans, their duration-aware recency variants (age times duration), exponential failure history per duration (weights 0.2, 0.5, 0.8 on newest), smoothed marginal failure frequency per duration, greedy coverage of distinct past failing cycles per duration over the last 32 cycles with marginal-risk tie break, and gradient-boosted tree failure probability per duration trained on preceding training cycles. Use deterministic numeric test ID for final ties. Fit the tree on training only and freeze weights. Choose each parameterized family by validation macro recall with declared grid order breaking ties. Select the strongest known family on validation as the primary comparator.

Retire the improvement claim if the chosen candidate fails to exceed the validation-selected comparator on either held-out project, or any known comparator matches or exceeds candidate macro recall on holdout. Retain all losses. Even if passed, require more independent projects and a dependence-aware uncertainty analysis before a venue claim. No clinical endpoints, human data, test execution, or manuscript changes.

Implementation details fixed before fitting or computing comparative outcomes. Use observed-cycle ordinal for age (one at the immediately following cycle), infinite age for a missing event, no transition for a first observation, and first execution verdict as the exponential estimator's initial state. Smooth the project backoff probability with Beta(1,1); use that project's past global probability when no observation exists for the context. The marginal frequency comparator uses strengths 2, 8 and 32. Greedy coverage keeps the last 32 cycle masks, then uses marginal risk per cost (strength 8) when marginal coverage ties. The tree is scikit-learn HistGradientBoostingClassifier with depth 3, 80 iterations, learning rate 0.1, early stopping disabled and one thread; use log duration, log exposure and failures, frequency, last verdict, failure/transition age, prior cycle burden and exponentially weighted failure rates. No current-cycle label enters a feature. Fit only at the training boundary. Store the validation selection before launching the held-out pass.
