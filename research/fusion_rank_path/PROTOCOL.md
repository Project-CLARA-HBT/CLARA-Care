# Exact sensitivity of judged top-ten ranks to two-score fusion

For a fixed query, how can we audit *every representable fusion weight* without mistaking a short-lived relevant result for a retrieval miss? The output is the ordered set of integer weights where each judged-positive document enters, leaves or changes rank in the top ten. This also suffices for exact nDCG@10 over the grid. The input includes relevance judgments because this is an offline evaluation procedure. It is distinct from predicting a weight for an unseen query.

Use the complete pinned development score arrays from the previous NanoBEIR study. Preserve all 150 queries, source grouping, self-match exclusion and stable document-ID ordering. Independently min-max normalize both score vectors after exclusions; round to nearest even unsigned 16-bit integer. Define blend at weight w in 0..65535 by the exact integer (65535-w)*a + w*b. Break all ties by earlier document ID. This is an explicit fixed-point scoring task. No claim about arbitrary real weights or unseen sources.

Baselines: (1) a relevance-aware exact sweep of all pair crossings with each positive; (2) the same sweep on the exact two-coordinate top-ten skyband, removing every row with at least ten coordinatewise dominators (stable endpoint orders); (3) a fused pass that stops work on a positive as soon as ten rivals outrank it at both endpoints. Candidate: apply the latter early elimination and use increasing-only and decreasing-only rank contributions to bound the feasible weight interval. If f rivals always outrank a positive, the (10-f)-th increasing crossing rules out all later weights, and only weights after enough decreasing crossings can be eligible. Select the two order statistics, discard irrelevant crossings and produce the exact clipped rank-change list. Compare a skyband-plus-candidate variant as a separate mandatory baseline. All arms must return identical ordered changes for every query; retain never-retrieved positives with their out-of-range rank. Include preprocessing in timing. Require a 20% median paired wall-time reduction against every registered competing family on each source to advance. Use 12 deterministic shuffled rounds across all arms in a single pinned WSL CPU process after one warmup; run identical in-memory queries once per round. Benchmark the complete per-source batch per arm, excluding input parsing and serialization. Machine load limits runtime inference. Repeat independent oracle checks over every weight and sampled full-sort controls, including tied endpoints, duplicate score pairs and simultaneous crossings. All runs are exploratory external development evidence.

Earlier work already identifies the upper envelope of linear score functions for line search in MERT, and database research studies ranking over multiple weight vectors. The empirical question is whether restricting the audit to judged items and clipping their rank to ten enables useful pruning beyond skyband and standard crossover processing. A fast implementation alone does not establish novelty.
