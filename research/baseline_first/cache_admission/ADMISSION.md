# Online admission development probe

The first screen found 20,916 and 16,085 recurrent misses shared by SIEVE and S3-FIFO at 1,024 objects. Test whether some workload namespaces exhibit more short-range reuse and thus warrant admission on first sight. The published key encoding preserves namespaces. We assume the first non-empty colon-delimited component marks a namespace when a colon exists and group remaining keys together.

Use SIEVE as the resident store. A bounded LRU history of four cache capacities tracks recent keys. On every access, the candidate admits a recent key. On a first access in that history, admit only when the namespace's estimated recent-key fraction exceeds the pooled fraction. Initialize both fractions to one half and update after making the decision, with one EWMA step of 1/256 per observation. Hash namespaces into 256 fixed bins using CRC32. Continue to refresh any resident hit. Use fixed settings for both clusters and all capacities. No future reuse or labels enter the method.

A control admits only recent keys and has the same history budget. Compare also with native W-TinyLFU (default settings), LFU and the three original policies. Require the original 5% development threshold against every comparator and no miss regressions at neighboring capacities. The ghost history and namespace statistics cost memory and are excluded from resident object capacity just as baseline metadata is. Even a success would require a physical-memory-matched comparison, multi-day traces, an independent operator and a distinct contribution beyond known class-based and frequency-based admission. This follow-up reuses both development prefixes.
