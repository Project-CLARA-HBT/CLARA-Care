# Development screen for online cache admission

Use the first 100,000 original rows of Twitter clusters 52 and 17, the first two workloads the data authors recommend for admission and eviction. Replay only get/gets in source order. Record the excluded operation counts. Use rows 1–20,000 to warm all policies and rows 20,001–100,000 for scoring. Unit-size objects and capacities of 256, 1,024 and 4,096 resident objects isolate eviction from size and TTL handling. This projection represents read-key locality. Production hit labels, mutation, expiry, backend costs and physical memory accounting are outside its scope.

Use the unmodified LRU, SIEVE and S3-FIFO policies in libcachesim 0.3.5, default policy settings with metadata accounting disabled. The primary endpoint is the count of read misses. Give each policy the same key at the same time. Independently check LRU and record each cache's misses split into previously observed and first-in-prefix keys. Report the number of misses common to both SIEVE and S3-FIFO. An oracle can use future reads to bound opportunities, but only online features could support a new method. Report both clusters and all capacities.

A method would merit testing on another operator's held-out traces only if its decision-time mechanism reduces misses by at least 5% relative to each baseline on each of the two development clusters at 1,024 objects, without increasing misses at either neighboring capacity. This is a screening threshold. Cluster prefixes within one operator do not establish external generalization.

The original authors released the trace under CC BY 4.0. This study extracts contiguous prefixes of the sorted compressed traces hosted by Carnegie Mellon.
