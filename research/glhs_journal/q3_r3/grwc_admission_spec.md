## 1. Executive Summary & Architecture Overview

Governed Read-to-Write Continuity (GRWC) establishes an auditable, fail-closed systems boundary between non-deterministic Large Language Model (LLM) agent inference and transactional health record persistence. 

In clinical decision support workflows, proposals generated by AI agents (`origin = "model"`) or adapted by human clinicians (`origin = "human_review"`) must prove exact disclosure continuity before state mutation can occur. Un-governed architectures suffer from proposal laundering, where model outputs strip provenance metadata, bypass snapshot verification, or downgrade to base-version-only write paths to evade validation.

GLHS R3 resolves these vulnerabilities by centralizing the **GRWC Admission Verifier** (`evaluate_grwc_admission()`) directly inside **Phase 3 (Revalidation under PostgreSQL Locks)** of the 6-Phase Atomic Commit Kernel (`execute_atomic_glhs_commit` in `commit_kernel.py`). This guarantees **same-transaction verification and write execution**, enforcing that revalidation, policy/consent checks, lineage verification, and domain table mutations execute atomically within the exact same database transaction under canonical OCC row and advisory locks.

```text

+-------------------------------------------------------------------------------------------------+
```

## 2. 6-Phase Atomic Commit Kernel Integration

All GLHS clinical state transitions execute through `execute_atomic_glhs_commit()` in `services/api/src/clara_api/glhs/commit_kernel.py`. The 6 phases run under transactional isolation:

### Phase 1: Fast Idempotency Pre-Check
Queries `GlhsAppliedTransition` by `(tenant_id, operation_kind, idempotency_key)` or `proposal_id`. If an existing committed record is found:
- If `request_digest` matches $\implies$ return cached `GlhsCommitResult` with `idempotent_replay = True`.
- If `request_digest` differs $\implies$ raise `GlhsInvariantError("idempotency_key_reused")`.

### Phase 2: Canonical Lock Acquisition (7-Class Lock Hierarchy)
Acquires total-ordered advisory and row locks to prevent race conditions and eliminate TOCTOU phantom drift:
1. **Class 1 (Global Policy):** `pg_advisory_xact_lock_shared` on global policy anchor.
2. **Class 2 (Domain Policy):** `pg_advisory_xact_lock_shared` on `policy_epoch:<domain>`.
3. **Class 3 (Subject Consent & Profile):** `SELECT ... FOR SHARE` on `User` and `PhrProfile`.
4. **Class 4 (Evidence Anchors):** `pg_advisory_xact_lock_shared` on `evidence:<evidence_id>`.
5. **Class 5 (Entity Version Partitions):** `SELECT ... FOR UPDATE` (WRITE) or `FOR SHARE` (READ) on `GlhsEntityVersionPartition` acquired in strict lexicographical order `(domain ASC, semantic_key ASC)`.
6. **Class 6 (Lease Anchors):** Advisory locks on reservation/lease keys.
7. **Class 7 (Idempotency Key):** `pg_advisory_xact_lock` EXCLUSIVE on `idempotency:<key>`.

### Phase 3: Freshness & Centralized GRWC Admission Revalidation Under Locks
Revalidates all governance, state version, dependency vector, and proposal lineage invariants while holding PostgreSQL locks:
- Base state version: `expected_base_state_version == current_version`.
- Policy epoch: `expected_policy_version == current_policy_version`.
- Consent version: `expected_consent_version == current_consent_version`.
- Entity partitions: `part.state_version == dep.observed_version` and digest equality.
- Evidence validity: `valid_from <= now <= valid_to` and `revoked_at is NULL`.
- **GRWC Admission Verifier:** Executes `evaluate_grwc_admission(db, profile_id, proposal_id, scope, ...)`.

### Phase 4: Domain Mutation Callback Execution
Invokes `mutation_callback(commit_context)`, supplying `GlhsCommitContext` which includes the verified `GrwcAdmissionResult`. The callback inserts canonical domain records (e.g. `GlhsClinicalCommitmentVersion` and `GlhsClinicalCommitmentTransition`).

### Phase 5: CAS Version Progression on Write Partitions
For each WRITE entity partition in lexicographical order:
$$\text{successor\_version} = \text{predecessor\_version} + 1$$
Executes `UPDATE glhs_entity_version_partitions SET state_version = :succ_ver WHERE id = :id AND state_version = :pred_ver`. Asserts `rowcount == 1`. If `0`, raises `GlhsInvariantError("cas_version_conflict")`. Records partition link predecessor/successor digests.

### Phase 6: Applied Transition & Transactional Outbox Persistence
Persists `GlhsAppliedTransition` with status `"COMMITTED"`, computes result digest, and emits transactional outbox event `glhs.commitment.transition.applied`.

## 3. GRWC Admission Verification Algorithm

The centralized admission verifier `evaluate_grwc_admission()` evaluates proposal lineage and exact disclosure constraints prior to Phase 4 callback execution:

```python
def evaluate_grwc_admission(
    db: Session,
    *,
    profile_id: int,
    proposal_id: int,
    scope: Any | None = None,
    actor_user_id: int | None = None,
    actor_role: str | None = None,
    purpose: str | None = None,
    task: str | None = None,
    current_state_version: int | None = None,
    effective_policy_version: str | None = None,
    effective_consent_version: str | None = None,
) -> GrwcAdmissionResult:
```

### 3.1 Lineage Graph Traversal & Bounded Depth Rule
Starting at proposal $P_0 = P$, the verifier follows parent proposal references ($P_{k+1} = P_k.\text{reviewed\_proposal\_id}$) to determine the root proposal $P_{\text{root}}$:

1. **Cycle Detection:** Maintains a visited set $S = \{P_0.\text{id}\}$. If $P_{k+1}.\text{id} \in S$, traversal immediately fails with:
   $$\text{GlhsInvariantError}("commitment\_lineage\_cycle\_detected")$$
2. **Depth Bound Guard:** Traversal bounds depth at $\text{MAX\_PROPOSAL\_LINEAGE\_DEPTH} = 4$. If depth $k > 4$, traversal fails with:
   $$\text{GlhsInvariantError}("commitment\_lineage\_depth\_exceeded")$$
3. **Missing Parent Guard:** If $P_k.\text{reviewed\_proposal\_id} \neq \text{null}$ but $P_{k+1}$ does not exist in the database:
   $$\text{GlhsInvariantError}("commitment\_lineage\_parent\_missing")$$

### 3.2 Immutable Lineage Invariants
Every descendant proposal $P$ derived from human review or adaptation MUST maintain immutable structural links to its root model proposal $P_{\text{root}}$ and inference binding $I_{\text{root}}$:

- **Root Proposal ID:** $P_{\text{root}} = \text{TraverseToRoot}(P)$.
- **Parent Proposal ID:** $P.\text{reviewed\_proposal\_id} = P_{\text{parent}}.\text{id}$.
- **Inference Context Binding ID:** If $P_{\text{root}}.\text{inference\_context\_binding\_id} \neq \text{null}$, then for all descendants $P$:
  $$P.\text{inference\_context\_binding\_id} = P_{\text{root}}.\text{inference\_context\_binding\_id}$$
  Stripping `inference_context_binding_id` or substituting a different binding ID raises `commitment_lineage_binding_required` or `commitment_lineage_binding_mismatch`.

### 3.3 Weak Binding-Mode Downgrade Prevention
Lineages initiated by THSS-consuming inference passes ($I_{\text{root}}.\text{consumed\_thss} = \text{True}$) MUST NOT be laundered into base-version-only proposals:

$$\forall P \in \text{Lineage}(P_{\text{root}}) : I_{\text{root}}.\text{consumed\_thss} = \text{True} \implies P.\text{context\_binding\_mode} = \text{"snapshot\_bound"}$$

- **Attempted Route Downgrade:** If $P.\text{context\_binding\_mode} = \text{"base_version_only"}$ when root consumed THSS $\implies$ raise `commitment_lineage_base_only_forbidden`.
- **Model Base Proposal Attempt:** Direct submission of $P.\text{origin} = \text{"model"}$ with $P.\text{context\_binding\_mode} = \text{"base_version_only"}$ $\implies$ raise `commitment_lineage_base_only_forbidden` / `model_base_proposal_forbidden`.
- **Human Review Downgrade Attempt:** If a human review modifies a model proposal to strip snapshot fields ($P.\text{source\_snapshot\_id} = \text{null}$) or alter mode $\implies$ raise `commitment_review_downgrade_forbidden`.

## 4. Standardized Rejection Reason Codes

GLHS R3 standardizes 8 stable rejection reason codes across all API entry points, commit kernel phases, database constraints, and evaluation schedules:

| Reason Code | Category | Failure Scenario & Trigger Condition | Architectural Enforcement Point |
| :--- | :--- | :--- | :--- |
| `commitment_lineage_base_only_forbidden` | Lineage Anti-Downgrade | Descendant proposal of a `consumed_thss=True` root proposal attempts to use `context_binding_mode="base_version_only"`, or model-origin proposal attempts base-only write path. | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `_require_lineage_binding()`; DB Check `ck_glhs_proposal_base_only_lineage_absent` |
| `commitment_lineage_binding_required` | Lineage Integrity | Proposal referencing a THSS snapshot lacks explicit `inference_context_binding_id`, or human review strips root binding reference. | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `_require_lineage_binding()`; DB Check `ck_glhs_proposal_binding_requires_snapshot` |
| `commitment_lineage_snapshot_mismatch` | Snapshot Identity | Descendant proposal `source_snapshot_id` differs from root proposal's or binding's `source_snapshot_id`, or binding exists with NULL snapshot. | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `_require_lineage_binding()` |
| `commitment_lineage_manifest_mismatch` | Disclosure Integrity | Proposal `source_snapshot_digest` differs from authoritative binding `source_manifest_digest`. | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `_require_lineage_binding()` |
| `commitment_lineage_cycle_detected` | Graph Integrity | Cyclic `reviewed_proposal_id` parent references detected during lineage graph traversal (e.g., $A \to B \to A$). | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `_resolve_proposal_lineage_root()` |
| `commitment_lineage_depth_exceeded` | Graph Integrity | Proposal lineage chain depth exceeds maximum limit ($\text{depth} > \text{MAX\_PROPOSAL\_LINEAGE\_DEPTH} = 4$). | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `_resolve_proposal_lineage_root()` |
| `commitment_review_downgrade_forbidden` | Human Adaptation Guard | Clinician or user review payload attempts to downgrade a snapshot-bound model proposal to base-version-only or strip snapshot binding fields. | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `review_model_commitment_proposal()` |
| `commitment_review_authority_required` | Governance Authority | Reviewer actor role lacks required domain authority specified in `CommitmentDomainPolicy.actor_roles`. | `commit_kernel.py`: `evaluate_grwc_admission()`; `commitment_gateway.py`: `review_model_commitment_proposal()` |

## 5. Formal Mathematical Predicate & TLA+ Invariant Mapping

### 5.1 Formal GRWC Admission Predicate

$$\begin{aligned}
\text{Admit}(P, t_c) \iff & \text{ValidLineage}(P) \\
& \land \text{AntiDowngrade}(P) \\
& \land \text{ContinuousDisclosure}(P, H, I) \\
& \land \text{StateCurrent}(P, S(t_c)) \\
& \land \text{GovCurrent}(P, G(t_c)) \\
& \land \text{DepsComplete}(P)
\end{aligned}$$

Where:

1. **$\text{ValidLineage}(P)$:**
   $$\begin{aligned}
   \text{ValidLineage}(P) \iff & \text{Depth}(P) \le 4 \land \text{Acyclic}(\text{Lineage}(P)) \\
   & \land (P.\text{reviewed\_proposal\_id} \neq \text{null} \implies P.\text{inference\_binding\_id} = P_{\text{root}}.\text{inference\_binding\_id})
   \end{aligned}$$

2. **$\text{AntiDowngrade}(P)$:**
   $$\begin{aligned}
   \text{AntiDowngrade}(P) \iff & (P.\text{origin} = \text{"model"} \implies P.\text{context\_binding\_mode} = \text{"snapshot\_bound"}) \\
   & \land (I_{\text{root}}.\text{consumed\_thss} = \text{True} \implies P.\text{context\_binding\_mode} = \text{"snapshot\_bound"})
   \end{aligned}$$

3. **$\text{ContinuousDisclosure}(P, H, I)$:**
   $$\begin{aligned}
   \text{ContinuousDisclosure}(P, H, I) \iff & I.\text{status} = \text{"COMPLETED"} \\
   & \land P.\text{source\_snapshot\_id} = I.\text{source\_snapshot\_id} \\
   & \land P.\text{source\_snapshot\_digest} = I.\text{source\_manifest\_digest}
   \end{aligned}$$
