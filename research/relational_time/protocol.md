# Compressing timestamp pairs when the parent row is available

Development question: after accounting for a foreign-key join and simple duration coding, does adapting a predictor to the event type and block improve lossless size? A physically stored timestamp pair is the unit of decoding. Each algorithm receives the same ordered medication rows, nullable second endpoint, code, encounter key, and parent encounter timestamps. Hold the input order fixed. The target is the marginal bytes needed for START and STOP when keys, codes and the parent are already available to the decoder. A standalone archive has a different cost. No patient decision or human label enters the evaluation.

Use both SHA-pinned Synthea CSV samples in the visit-refresh protocol as development data. Include all medication records including reversed and missing stops. Recreate every UTC second and null in order. Count encoded bytes including all transform flags, parquet framing, and block boundaries. Use the same Parquet writer, zstd level, integer types and null handling. Compare native plain, dictionary and DELTA_BINARY_PACKED encoding; a row-local duration residual; a join residual using the parent encounter start; and a code-conditional residual based on the previous occurrence's duration and parent offset. Missing parents predict zero. A trained codebook is unnecessary because each side can construct identical state from preceding decoded rows. Use the best fixed combination retrospectively as an optimistic comparator. Test per-block selection with 4,096 rows and a serialized selector; retain every increase in size. A credible result needs to beat the strongest fixed predictor and replicate outside Synthea. Conditional residual coding, delta encoding and foreign-key correlations have substantial prior work. Superiority to ordinary Parquet alone is insufficient.
