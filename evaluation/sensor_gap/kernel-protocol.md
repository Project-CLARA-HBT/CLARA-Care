# Conditional kernels on equipment temperature gaps

Development follow-up to the matched conditional-regression study. Test whether changes in *observed loads inside the outage* explain reconstruction error beyond the adjacent temperatures. Use exactly the same masks, station-specific chronological partitions, primary MAE, bootstrap and five-percent margin. Keep previous negative studies visible. Disjoint sensor deployment remains untested.

Add six electrical load features at each of six equal segments inside the gap. Average each load in each segment, then subtract the line interpolating that load across the two observed endpoints of the outage at the segment midpoint. This measures excursions in demand. Each method has access to the identical records. Compare the prior pooled ridge and other frozen arms; a pooled linear ridge using all features; a temperature-only Gaussian kernel ridge; a Gaussian kernel on the concatenated standardized temperature and load coordinates; and the candidate additive kernel that averages the two separate Gaussian similarities. The mechanism would preserve similarity of the temperature context when load excursions disagree, and vice versa. Additive and product kernels are established techniques. A benefit from extra covariates alone does not support the mechanism.

Use training-only standardization and the same final-quarter temporal validation per station and duration. Separate training and validation by 168 hours measured between gap starts to prevent overlap of feature windows. For kernel arms select bandwidth multiplier from 0.5, 1, 2 relative to median positive squared training distance and diagonal regularization from 0.01, 0.1, 1. For the linear arm select penalty 3, 30, 300. Minimize validation MAE (ties in listed order), refit all training cases and evaluate. Predict residual from the training-only periodic bridge used previously. For validation the daily profile is fitted strictly before the first validation input flank, with a further seven-day buffer. Run kernels and linear solves in float64 on the linked WSL GPU. Retain per-outage predictions' errors and calibration decisions; wall time under shared GPU load is outside the endpoints.
